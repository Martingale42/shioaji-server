# P3 Timed-Out Order Adoption (BL-1) Implementation Plan

> **For Claude:** Use superpowers:executing-plans or superpowers:orchestrator-driven-development to implement this plan.
> **⚠️ Cross-repo:** gateway part in `shioaji-server@main`; adapter part in `nautilus_trader@sinopac-adapter-clean`. Confirm `git branch --show-current` before each commit; never mix repos in one commit.

**Goal:** Make a sinopac order whose HTTP `place_order` timed out (left `SUBMITTED`, no `venue_order_id`, mapping unset) be **adopted** by later WS events / reconciliation instead of spawning a duplicate external order — by round-tripping a short token through Shioaji's `custom_field` so the original `client_order_id` is always recoverable.

**Architecture:** NT reconciliation adopts an order when an `OrderStatusReport` carries the order's REAL `client_order_id` (verified: `live/execution_engine.py` matches on `_cache.order(report.client_order_id)`; a synthetic id creates an external order instead). Shioaji's `Order.custom_field` is only 6 ASCII chars (`ConStrAsciiMax6`), too small for a full `client_order_id`, so we store a **deterministic 6-char hash token** of the `client_order_id`. On any later event the adapter recovers the original id by matching the token against in-cache orders (recomputing the hash) — restart-safe, no persisted map required. Mirrors the Hyperliquid cloid pattern.

**Tech Stack:** Python (FastAPI gateway; NT `LiveExecutionClient`), Rust (pyo3, serde), Shioaji SDK, maturin/cargo.

**Design reference:** `docs/plans/2026-06-08-backlog-fixes-design.md` (BL-1). Background: prior P3 fix (`4f6bb70253`) + I2 correction already removed the false-reject hidden exposure; this closes the remaining duplicate-external-order gap.

**Project rules:** Python via `uv run` (adapter tests: `uv run --active --no-sync pytest …` — bare `uv run pytest` fails; do NOT re-sync the venv, it drops the built extension). Rust: no `unwrap()/expect()` on external data; `make build-debug` before Python tests that depend on Rust. Commits explain WHY in Traditional Chinese, NO AI attribution, never `--no-verify`. Real-money correctness is a red line.

### Task 4: Adapter Python — token round-trip + adopt (nautilus_trader)

**Files:**
- Modify: `nautilus_trader/adapters/sinopac/execution.py`
- Test: `tests/integration_tests/adapters/sinopac/test_execution.py` (extend)

**Implementation:**
1. Token helper (module-level), deterministic + restart-safe:
   ```python
   import hashlib, string
   _B62 = string.digits + string.ascii_letters
   def _coid_token(client_order_id: str) -> str:
       """6-char base62 hash of a client_order_id (fits Shioaji custom_field<=6)."""
       h = int.from_bytes(hashlib.blake2s(client_order_id.encode(), digest_size=8).digest(), "big")
       return "".join(_B62[(h >> (6*i)) % 62] for i in range(6))
   ```
2. `_submit_order` (~:420-433): set `custom_field=_coid_token(order.client_order_id.value)` on the HTTP place_order call; keep the existing `_trade_id_to_client_order_id[...]` population on success unchanged.
3. Add a recovery helper used by `_handle_deal_event` (~:350), `_handle_order_status_event` (~:241), and `generate_order_status_reports` (~:632):
   ```python
   def _resolve_client_order_id(self, event_or_trade) -> ClientOrderId | None:
       # 1) existing trade_id mapping (fast path, unchanged)
       # 2) custom_field token -> match against cache orders by recomputing _coid_token
       token = event_or_trade.get("custom_field")
       if token:
           for o in self._cache.orders_open():           # or all non-terminal orders
               if _coid_token(o.client_order_id.value) == token:
                   self._trade_id_to_client_order_id[trade_id] = o.client_order_id.value  # backfill
                   return o.client_order_id
       return None  # caller falls back to synthetic SINOPAC-{trade_id}
   ```
   In `generate_order_status_reports`, use this BEFORE synthesizing `SINOPAC-{trade_id}`, so a timed-out order's report carries its REAL `client_order_id` → NT adopts it (attaches `venue_order_id`, advances state) instead of creating an external order.

**Tests (Required — financial correctness):**
- **Session timeout adopt:** mock `place_order` raising `TimeoutError` (order stays SUBMITTED, no mapping); feed a later event/trade carrying `custom_field=_coid_token(coid)` → `_resolve_client_order_id` returns the original `client_order_id`; the reconciliation report carries it (not synthetic).
- **Restart adopt:** clear `_trade_id_to_client_order_id` and `_token_to_*` caches; only the NT cache has the SUBMITTED order → recovery still resolves via recomputed hash.
- **No regression:** the prior P1/P2/P3 tests still pass; when `custom_field` is absent, behavior falls back to the synthetic id (unchanged).
