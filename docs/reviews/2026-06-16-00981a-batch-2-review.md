## 數學正確性手動推演結論（關鍵）

### Backward reconstruction 符號 + ex-date 邊界:**正確**

**公式**(`scripts/universe_ranking.py:39-41`):
`shares(code, d) = current_shares(code) − Σ{ delta_e : effective_date(e) > d }`

**符號驗證（手動推演 + polars 實測，混合正負 delta）:**
- 錨點 `current = 1000`；事件 `+100 @ 06-10`、`−50 @ 06-20`；交易日 `[06-01, 06-10, 06-20]`。
- `06-01`:兩事件皆 future → `1000 − (100 + (−50)) = 950`。✅
- `06-10`:僅 `06-20` 為 future → `1000 − (−50) = 1050`；`06-10` 當日事件**不**算 future（已套用）。✅
- `06-20`:無 future 事件 → `1000`（完整錨點）。✅
- **符號方向正確**:資本**增加**（delta > 0）在未來生效 ⇒ 過去股數較少 ⇒ 正確被減去。
  資本**減少**（delta < 0）在未來生效 ⇒ 過去股數較多 ⇒ 減去負數即加回 ⇒ 正確。
  測試 `test_reconstruct_capital_decrease_negative_delta` 釘住此案例（`800 − (−200) = 1000`）。

**ex-date 邊界 strict `>` 而非 `>=`:正確**（`scripts/universe_ranking.py:73`,
`.filter(pl.col("effective_date") > pl.col("date"))`):
- 在 ex-date 當日，該事件**不**計入 future，故當日即套用 post-event（current）股數。
- 這與 spike 文件的 TWT49U ex-date 語意一致:`資料日期`（除權日）就是新股數生效日，
  當日收盤已是除權後價格，故股數亦應為除權後值。**符號翻轉或 off-by-one 會靜默污染整個宇宙——
  此處未犯。**
- 測試 `test_reconstruct_applies_event_backward`（事件日 = `1100`，前一日 = `1000`）與
  `test_reconstruct_two_events_accumulate_backward`（`06-10` 當日 = `950`，含「event-day is on/after」
  註解）直接釘住邊界。

### Minor

**M1 — `_to_float` 空字串回 `0.0` 而非 `None`，與 docstring 矛盾**
`scripts/twse_tpex_market.py:443-445`
```python
cleaned = raw.replace(",", "").strip()
if not cleaned or cleaned in {"--", "---", "0.00"}:
    return None if cleaned in {"--", "---"} else 0.0
```
- `cleaned == ""`（空白收盤欄）落入 `else` → 回 `0.0`，但 docstring 寫「float, or None if not
  parseable」。空字串應視為不可解析（→ None），讓 `compute_market_cap` 的 inner-join 丟棄該列，
  而非產生 `mktcap = 0`。
- `"0.00"` → `0.0` 同理。
- **影響為良性**:`mktcap = 0` 在當日排最後，絕無可能擠進真正的 top-300（真 top-300 股不會有 0 收盤），
  故**不影響聯集正確性**。但污染中間資料、且與 docstring 不符（誠實性）。建議:空字串與 `"0.00"`
  皆回 `None`，docstring 與行為對齊。

**M2 — line 488 type-flag:benign（非真 bug）**
`scripts/twse_tpex_market.py:488` `delta = deltas.get(e["code"])`
- `e` 為 `dict[str, object]`，故 `e["code"]` 靜態型別為 `object`；`deltas` 為 `dict[str, int]`，
  其 `.get()` 期望 `str` 鍵——型別檢查器即對此 `object → str` 報警。
- **runtime 安全**:`e["code"]` 實際永遠是 str（由 `_fetch_twt49u_ex_dates` 建構為
  `str(rec[1]).strip()`），dict 查找對 str 鍵正常運作。純靜態型別雜訊，非真 bug。
- 建議（可選）:`str(e["code"])` 包一層消除警告，或將 ex_events 改用具名 dataclass / TypedDict。

**M3 — `_TPEX_CODES` 為 module-global 可變狀態**
`scripts/twse_tpex_market.py:355-367`（`set_tpex_codes` + `_is_tpex_code`）
- `fetch_daily_close` 的 TWSE/TPEx 路由依賴 module-global `_TPEX_CODES`，由 orchestrator 先呼叫
  `set_tpex_codes` 填入。可運作（orchestrator `build_00981a_universe.py:97` 確有先設），但 global
  可變狀態在多次呼叫 / 測試間有順序脆弱性，且 `fetch_daily_close` 的純函式介面（`codes` list）
  與隱藏的 global routing 表耦合。
- **影響有限**:此模組 brief 標示為網路 I/O 層、測試 deferred（純邏輯在 Task 3 測）。建議（可選）:
  將 market 標記隨 codes 一併傳入（例如 `list[tuple[code, market]]` 或 dict），消除 global。

**M4 — `_to_int` 對非整數小數靜默截斷**
`scripts/twse_tpex_market.py:144` `return int(float(cleaned))`
- 發行股數預期為整數字串（如 `"160,200,000"`），`int(float(...))` 對含小數點的輸入會截斷。對
  此 dataset 為良性（股數本即整數），但若上游格式異動（科學記號 / 小數）會靜默失真而非報錯。
  純防禦性備註，非當前缺陷。
