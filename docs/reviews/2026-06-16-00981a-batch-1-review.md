## 對 GO 裁決誠實度的評估

**GO 站得住腳,且無被隱藏的家族失敗。** 理由:

1. **sanity-check 是真交叉驗證,非斷言。** 我發現 doc 用作獨立對照的 19,194,960,000 並非杜撰——
   它是 t05st09sub 同一列的 **cell[13](現金股利總額)**,是 MOPS 獨立揭露的欄位,**與 t187ap03_L
   發行股數錨點無資料血緣**。因此「現行股數錨點」與「現金股利反推基數」確為兩條獨立資料路徑,交叉驗證有效。

2. **重建的「方向(sign)」被驗證,而非僅幅度。** 錨點 − delta 把 pre-event 推到錨點**之下**,而兩個獨立
   基數(15,995.8M 與 16,020.0M)都同樣低於錨點,且**夾住**重建值(15,995.8M < **16,013.8M** < 16,020.0M)。
   若 executor 把事件方向搞反(錨點 + delta),重建會落在 16,334,200,000,遠高於所有獨立基數——
   不會出現這種「被夾住」的吻合。**故 0.11% 並未掩蓋 sign 錯誤。**

3. **0.11% 殘差解釋可信(treasury/record-date),且我有量化佐證。** 兩個 MOPS 內部「配息/配股適格基數」
   彼此就差 24,200,000 股 = **0.1511%**(現金股利基數 vs 配股基數),這個差異**先於錨點介入就存在**,
   來源正是各事件適格股數(排除庫藏股、基準日差異)不同。換言之 0.11% 量級的殘差是兩個揭露基數本身
   固有的離散度所致,**而非重建的幅度誤差**。doc 的「rounding/庫藏股容差」解釋因此成立。

4. **若任一家族失敗會暴露。** 我對每個家族至少獨立命中一次(多數兩次,含窗頭 2025-05 與窗尾 2026-06),
   stat 旗標、列數、欄位鍵全部對齊;沒有「只測一檔就外推全市場」的隱性破綻被掩蓋。

2. **[家族 2b 備註, 行 96] 舊 TPEx php 端點的失效模式描述不精確。**

   **結論不變(勿用該端點)正確**,只是「302」這個確切失效碼可能視環境而異;建議改述為「已停用 / 不可用」。

   doc 說 0.11% 殘差在「rounding/庫藏股容差內」。實測顯示更強的佐證:**兩個 MOPS 內部適格基數彼此就差
