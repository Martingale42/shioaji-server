## Findings (ranked most-severe first)

### Important — correctness / completeness

**F1 — Capital reductions & conversions are never emitted as events** `scripts/twse_tpex_market.py` (`fetch_capital_events`)
Events are sourced only from TWT49U **權** ex-dates ∩ MOPS positive stock-dividend deltas
(cell[16]), and `if delta is None or delta == 0: continue`. Capital reductions (減資, negative
delta) and convertible-bond / GDR / private-placement conversions carry no 權 ex-date and/or a
non-positive delta, so they are structurally invisible — despite design §A listing
「增減資/股票股利/減資/可轉債轉換」 and the `kind`/signed-`shares_delta` schema promising generality.
*Impact:* a code that did an in-window 減資 is treated as constant at its (smaller) post-event
share count, **overstating** pre-event mktcap; a code that did a large 現增/conversion has it
understated. Either can wrongly include/exclude it from the daily top-300 → survivorship bias in
the union. Bounded on a 395-code *superset* (erring large is safer) but unquantified without R4.

**F2 — Non-atomic cache write + existence-only validity (PROVEN failure)** `scripts/twse_tpex_market.py` (close ~L323, current_shares ~L229, capital_events ~L502; read guards ~L189/L299/L469)
`if cache_path.exists(): return pl.read_parquet(...)` with no size/readability check, and
`df.write_parquet(path)` with no temp-file+rename. A SIGKILL mid-write leaves a zero-byte/truncated
parquet that the next run treats as "cached" → either `pl.read_parquet` aborts the whole build, or
a silent permanent gap. **This actually happened**: the original run was killed 2026-06-17 04:49
mid-write, leaving `cache/twse_tpex/close/6294/202605.parquet` at 0 bytes; recovery required manual
detection + deletion. *Fix:* write to `*.tmp` then `os.replace`; on cache read, validate
size>0 / parseable (delete+refetch if not).

**F3 — Multiple in-window ex-dates per code each receive the full year-summed delta** `scripts/twse_tpex_market.py` (`fetch_capital_events` delta loop)
`deltas` is a `dict[code -> delta]` summed over the fetched ROC years; the loop assigns
`deltas.get(e["code"])` to **every** ex-date of that code. A code with two in-window ex-dates
(e.g. a 2025 and a 2026 stock dividend) gets the full multi-year sum applied at *both* dates;
`reconstruct_daily_shares` then subtracts it twice for early-window days → mis-stated shares/mktcap.
*Fix:* match each delta to its specific ex-date (per (code, fiscal-year) keying), not per-code.

**F4 — Failed fetch is indistinguishable from "legitimately no data"; empty payloads are cached** `scripts/twse_tpex_market.py` (MOPS ~L562, current_shares ~L227, capital_events ~L500)
After `MAX_RETRIES`, the MOPS POST loop sets `html=""` and `continue`s the (market, year) with only
per-attempt warnings; a total outage yields the same empty result as a year with no dividends. The
empty frame is then `write_parquet`'d and cached, so a transient outage is **frozen** as the
authoritative (empty) event/anchor set and no resume re-pulls it. *Fix:* distinguish
fetch-failure from empty-result; never cache a frame built entirely from failed pulls; surface a
degraded-run signal to the orchestrator.

**F5 — `_to_float` returns 0.0 for `""`/`"0.00"` instead of None** `scripts/twse_tpex_market.py:432`
`if not cleaned or cleaned in {"--","---","0.00"}: return None if cleaned in {"--","---"} else 0.0`
— blank cells and the `"0.00"` suspended-day sentinel are coerced to a *real* close of 0.0 (only
`--`/`---` map to None). compute_market_cap keeps the row (mktcap=0), so the code is
present-but-ranked-last that day rather than absent → can spuriously split a membership interval.
*Fix:* treat `""`/`"0.00"` as None (missing), consistent with `--`. (Already-cached parsed values
are unaffected by a forward fix; impact is limited to rare blank/0.00 days and is bounded.)

### Important — robustness / design depth

**F6 — Cache keyed only on file existence, not on (window, code-set, fetch-date)** `scripts/twse_tpex_market.py`
A re-run with a later `--end` (the intended periodic-rebuild case) cache-hits the prior
`current_shares.parquet` / `capital_events.parquet` and silently uses the stale anchor + event set
for the extended window. *Fix:* key/validate the cache on the parameters that determine its
contents, or version the cache by fetch-date.

**F7 — TWSE/TPEx routing via mutable module global** `scripts/twse_tpex_market.py` (`_TPEX_CODES` / `set_tpex_codes` / `_is_tpex_code`; dead `all_codes` param)
`fetch_current_shares` already returns a per-row `market` column (correct depth), but
`fetch_daily_close` discards it and re-derives the market via hidden module state. A caller that
forgets `set_tpex_codes` (a test, a re-use, parallel builds) silently routes every TPEx code to the
TWSE endpoint → `stat != OK` → empty closes → those stocks silently absent from the universe, with
no error. *Fix:* thread the per-code `market` field into `fetch_daily_close`; drop the global + the
unused `all_codes` parameter. (Also raised as Batch-2 review M3.)

### Minor — cleanup / efficiency / conventions

**F8 — `build_union_and_membership` rescans the full frame once per union code** `scripts/universe_ranking.py:174`
Python loop + `daily_top.filter(pl.col("code")==code)` is O(codes×rows). A single
`group_by("code")` with a vectorized gap/run-id expression replaces hundreds of full passes. Also:
`daily_top_n` does a second full `group_by("date")` pass for short-day warnings that the existing
rank column already provides; `reconstruct_daily_shares` cross-joins every code × trading-day before
filtering (event-free codes pay the full cost). Data is small today, so this is maintainability/perf
hygiene, not a correctness issue.

**F9 — Duplicated month-close parse loop** `scripts/twse_tpex_market.py` (`_fetch_twse_month_close` / `_fetch_tpex_month_close`)
The ~12-line record→{code,date,close} parse loop is duplicated verbatim across the two fetchers;
only URL/params and record extraction differ. A shared `_parse_close_records(records, code)` helper
removes the fix-drift risk (e.g. a future change to the close-sentinel rule must currently be made
twice).

**F10 — `_to_float` missing mandatory `Formula` docstring section** `scripts/twse_tpex_market.py:432`
~/.claude/CLAUDE.md: "Every function performing a mathematical operation MUST contain, in this
order: Definition / Formula / Domain / Returns." `_to_float` has Definition/Domain/Returns but no
Formula; its sibling `_to_int` does, confirming the authors classify these as math helpers.
(Fixed naturally alongside F5.)

**Also noted (low/refuted):** `roc_years` fiscal-year mapping assumes ex-year−1 (fragile for
late/special dividends, but the default 2025-05..2026-06 window is covered); `shares = capital/par`
fallback precision (float64 is exact for all realistic TW share counts < 2^53 — effectively a
non-issue); 9 partial-coverage codes are tiny TPEx names with zero top-300 impact (already accepted).
