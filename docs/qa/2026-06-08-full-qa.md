## 2. 逐項驗收（使用者視角 + 證據）

### G5 / G6 — WebSocket handler 韌性
`tests/test_ws_resilience.py` 三個案例全綠，且斷言到位（非僅「測試存在」）：

- **G6 壞 JSON 不斷線**（`test_bad_json_returns_error_and_keeps_connection`）：
  首個 frame 為 `"not json"` → 回 `{"type":"error","detail":"Invalid JSON"}`，**第二個合法 frame 仍被處理**（`type=="subscribed"`），收尾後 `active_connections == []`（無殭屍）。
- **G5 未登入拒絕訂閱**（`test_subscribe_before_login_is_refused`）：
  `connected=False` → 回 `{"type":"error","detail":"gateway not connected"}`，`resolve_contract` **未被呼叫**（沒碰 SDK），`subscriptions == {}`。
- **G5 動作失敗無殭屍/無孤兒**（`test_action_error_does_not_leak_zombie_or_orphan`）：
  `resolve_contract` 拋 `ValueError` → 回 error frame、loop 存活；`finally` 同時釋放 WS 連線與孤兒 Shioaji key（`resolve_contract.call_count >= 2`，證明走了 `_unsubscribe_orphaned` 清理路徑）。

**源碼佐證**：`src/shioaji_server/app.py:234-238` 的 `finally` 區塊永遠 `manager.disconnect(ws)` + `await _unsubscribe_orphaned(...)`；`gateway not connected` 守門在 `app.py:180`。

### G7 — 純期貨帳號 `/api/orders/trades` 回 200（非 500）
`src/shioaji_server/routes/orders.py:38-45`：

```python
def _list_trades_sync(api):
    if api.stock_account is not None:
        api.update_status(api.stock_account)
    if api.futopt_account is not None:
        api.update_status(api.futopt_account)
    return api.list_trades()
```

純期貨登入時 `stock_account is None`，**不會呼叫 `update_status(None)`**（這正是舊版觸發 SDK 內部 500 的根因），對稱地處理 stock/futopt 兩側 → 回 200。`account.py` 的 `positions`/`pnl` 對 `stock_account is None` 回 **400**（明確的 client error，非 500 崩潰，屬設計預期）。
